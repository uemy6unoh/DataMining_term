## 1. 요약

| 항목 | v1 | v2 |
| --- | --- | --- |
| 데이터 | 413,720행 (중복, 좌표 어긋남 포함) | 122,019건 (거래 1건 = 1행) |
| 검증 | 거래 단위 무작위 분할 | 건물 단위 분할 + 최종 시험용 건물 20% |
| 월부담액 | 전환율 4% 가정 | 실거래에서 찾은 전환율 (아파트 4.35%, 연립다세대 4.62%) |
| 아파트 R² | 0.935 | 0.816 (처음 보는 건물 기준) |

| 결과물 | SHAP 요인 분석 | 적정 월세 확인 화면 (Streamlit, HTML 데모) |

v2의 R²가 낮은 건 평가 기준을 바꿨기 때문임. 같은 거래의 복사본이 학습과 시험에 함께 들어가던 문제를 없애고, 처음 보는 건물을 얼마나 맞히는지로 다시 쟀음

## 2. 데이터 다시 만들기 ([01_data_fix.ipynb](01_data_fix.ipynb))

v1 최종 데이터에서 두 가지 문제를 찾음

| 문제 | 원인 | 규모 |
| --- | --- | --- |
| 같은 거래가 여러 번 들어감 | 행정동 매핑표와 **법정동 이름**으로 merge (법정동 1개가 행정동 여러 개라 1:N) | 거래 1건당 평균 3.6행 |
| 거래와 좌표가 다른 행에 붙음 | 좌표 쪽 컬럼이 7460행부터 한 칸씩 밀림 | 주소의 동과 좌표의 동이 맞는 행 13.9% |

![동 일치율](images/01_dong_match.png)

고친 방법
1. 원본 실거래에서 v1 필터를 그대로 다시 적용 (122,474건, v1 노트북과 같은 수)
2. 같은 주소가 나올 때마다 주변에 있는 같은 법정동 좌표에 투표하고, 동마다 주소 1개 = 좌표 1개가 되도록 매칭 (헝가리안 알고리즘)
3. 입지 변수(병원, 역, 공원 등 반경 개수, 인구 비율)는 복구한 좌표 기준으로 다시 붙임

| 검증 | 결과 |
| --- | --- |
| 원래 짝이 맞던 앞부분 주소 1,155개와 비교 | 99.9% 일치 |
| 도로명 주소가 같은 건물(62개)의 좌표 거리 중앙값 | 3,521m에서 45m로 |
| 공원 개수를 원본 데이터로 다시 계산 | 100% 일치 |

최종 데이터는 122,019건 (아파트 58,985건, 연립다세대 63,034건)

## 3. 검증 방식 바꾸기 ([02_validation.ipynb](02_validation.ipynb))

아파트는 단지 하나에 거래가 평균 11건이라, 거래를 무작위로 나누면 시험 거래 대부분이 같은 단지의 다른 거래를 학습에 갖고 있음. 기존 데이터에서는 시험 행의 89.4%가 학습 데이터에 똑같은 행이 있었음  
그래서 같은 건물(지번, 도로명 주소, 아파트 단지)을 묶어서 건물 단위로 나눔

| 같은 변수, 같은 설정 | 무작위 분할 | 건물 단위 5-fold |
| --- | --- | --- |
| 아파트 R² | 0.931 | 0.832 |
| 연립다세대 R² | 0.758 | 0.636 |

- 건물 20%는 최종 시험용으로 먼저 떼어두고, 반경 조합, 튜닝, 변수 선택은 나머지 80% 안에서만 정함
- 반경 조합을 다시 고르면 아파트 0.827에서 0.835, 연립다세대 0.602에서 0.623으로 조금 오름. 다만 fold 간 편차(0.02~0.12)보다 작아서, 반경 선택보다 데이터와 검증 방식이 훨씬 큰 차이를 만들었음

![반경 조합 비교](images/02_radius.png)

## 4. 모델과 해석 ([03_model.ipynb](03_model.ipynb))

### 전환율
v1은 보증금을 월 부담으로 바꿀 때 연 4%를 가정했음. 같은 건물, 같은 면적, 같은 달 계약끼리 보증금과 월세 차이를 비교해서 실제 전환율을 찾음

월부담액 = 보증금 × 전환율 ÷ 12 + 월세

| 구분 | 전환율 | 비교한 거래 |
| --- | --- | --- |
| 아파트 | 4.35% | 29,580건 |
| 연립다세대 | 4.62% | 4,257건 |

![전환율](images/03_rate.png)

4%로 해도 성능과 중요 변수 순위는 거의 같음. 서비스의 보증금, 월세 환산에는 실제 비율이 맞아야 해서 찾은 값을 씀

### 튜닝과 변수 선택
- 트리 수를 늘리고 학습률을 낮춘 설정으로 오차율이 아파트 23.3%에서 21.9%, 연립다세대 22.4%에서 22.0%로 줄었음
- 위도, 경도를 넣으면 조금 좋아지지만 "위도 +5만원"처럼 설명이 안 돼서 뺐음. 이 프로젝트는 가격의 이유를 보여주는 게 중요해서 설명할 수 있는 변수만 남김
- 주변 건물 평균 시세는 오히려 나빠져서 뺐음

### 최종 시험 (처음 보는 건물)

| 구분 | 설정 | MAE (만원) | R² | 오차율 중앙값 |
| --- | --- | --- | --- | --- |
| 아파트 | v1 설정 | 39.6 | 0.822 | 12.8% |
| 아파트 | v2 설정 | 37.8 | 0.816 | 11.8% |
| 연립다세대 | v1 설정 | 16.2 | 0.589 | 12.6% |
| 연립다세대 | v2 설정 | 15.8 | 0.608 | 12.6% |

- MAE와 오차율은 둘 다 좋아짐. 아파트 R²는 아주 비싼 집 몇 건의 큰 오차 때문에 조금 낮게 나와서 오차율을 같이 봄
- 이미 거래가 있던 건물의 새 계약이면 아파트 R² 0.939 (오차율 중앙값 7.0%), 연립다세대 0.753 (10.7%)

### SHAP으로 본 가격 요인
holdout 건물 3,000건 기준. 값은 평균적으로 월부담액을 몇 만원 움직였는지

| 순위 | 아파트 | 연립다세대 |
| --- | --- | --- |
| 1 | 전용면적 (84.1만원) | 전용면적 (17.0만원) |
| 2 | 건축년도 (34.5만원) | 건축년도 (15.0만원) |
| 3 | 자치구 (21.5만원) | 자치구 (4.9만원) |
| 4 | 법정동 (12.7만원) | 65세 이상 인구 비율 (3.5만원) |
| 5 | 19세 이하 인구 비율 (12.5만원) | 법정동 (3.1만원) |
| 6 | 65세 이상 인구 비율 (5.6만원) | 계약개월수 (2.9만원) |

- 면적, 연식, 위치(구, 동)가 대부분을 설명함
- 아파트는 19세 이하 비율이 높은 동네일수록 비쌈. 학군 수요로 보임
- 연립다세대는 계약기간이 길수록 많이 쌈. 공공임대(장기 계약)가 섞여 있는 영향으로 보임
- v1에서 중요하게 봤던 역, 공원 개수는 상위권에 없음. v1 해석은 좌표가 어긋난 데이터에서 나온 거라 근거가 약해졌고, 역과 공원 효과는 구, 동 정보에 이미 들어가 있는 것으로 보임

## 5. 적정 월세 확인 화면

서울에서 처음 월세를 구하는 사회초년생, 대학생이 "이 가격이 괜찮은지" 판단할 수 있게 만든 화면  
v1 시사점의 "세입자의 합리적 판단 지원", "정량 근거로 협상"을 실제로 쓸 수 있는 형태로 옮김

| 기능 | 내용 |
| --- | --- |
| 적정가 판단 | 이 매물 월부담액이 비슷한 조건 거래 100건 중 싼 쪽에서 몇 번째인지 |
| 가격 설명 | SHAP으로 집 조건, 위치, 동네 인구, 주변 시설이 각각 몇 만원씩 더하고 뺐는지 |
| 보증금 바꿔보기 | 보증금을 바꾸면 월세가 얼마여야 같은 부담인지 |
| 같은 건물 실거래 | 면적이 비슷한 2024년 거래 |
| 주의 안내 | 시세보다 많이 싸면 등기부등본, 건축물대장 확인 안내 |

- 적정 범위는 거래가 있던 건물의 새 계약을 모델이 맞혔을 때의 오차로 잡은 80% 범위이고, 같은 건물 거래가 많을수록 좁아짐
- 예시 (위 그림) : 강남구 개포동 개포2차현대 77.75㎡, 보증금 6억 5천 / 월세 40은 월부담액 276만원, 적정 범위 201~313만원으로 "비싼 편". 같은 건물의 보증금 1억 / 월세 240 계약도 월부담액이 276만원이라, 찾은 전환율이 실제 거래와 잘 맞음

| 활용 | 내용 |
| --- | --- |
| 세입자 | 계약 전에 적정 범위와 같은 건물 실거래를 근거로 가격 협상 |
| 부동산 플랫폼 | 매물 상세에 적정가 범위 표시, 시세와 크게 다른 매물 따로 표시 |
| 공공 상담 창구 | 전월세 상담 때 근거 자료로 활용 |

### 실행 방법
**HTML 데모** : [demo/rent_check_demo.html](demo/rent_check_demo.html) 을 받아서 브라우저로 열기. Streamlit 화면과 같은 모델을 브라우저에서 계산함 (예측값 차이 0.001만원 미만)

**Streamlit**
```
cd v2/streamlit
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

## 6. 한계
- 2024년 거래만 써서 그 뒤 시세 변화는 반영 안 됨. 운영하려면 매달 새 실거래로 다시 학습하고 오차가 커지는지 계속 봐야 함
- 화면에서는 2024년에 거래가 있던 건물만 고를 수 있음
- 공공임대를 아직 못 걸러서 월부담액이 아주 낮은 구간은 오차가 큼
- 연립다세대는 보증금 3천만원 미만에서 실제 전환율이 거의 0%라 보증금 환산이 덜 맞을 수 있음
- 식당, 병원, 파출소, 대학 개수는 v1에서 계산한 값을 좌표 기준으로 다시 붙인 것 (공원만 원본으로 다시 계산해서 확인)
